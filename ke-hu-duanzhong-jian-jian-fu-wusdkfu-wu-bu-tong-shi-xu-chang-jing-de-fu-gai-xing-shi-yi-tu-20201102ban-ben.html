客户端/中间件服务/SDK服务不同时序场景的覆盖性示意图20201102版本

十一月 2, 2026 HEIN

以下针对自动落锁、ESC。“客户端”包含 API 包，缓存读取、补发由 API 内部完成，业务方只需注册监听。

1. 客户端先注册，中间件或 SDK 稍后就绪

sequenceDiagram
    participant C as 客户端及API
    participant M as 中间件服务
    participant S as SDK服务
    C->>C: 注册状态监听
    M->>M: Controller.init完成
    M-->>C: 模块就绪，通知onServiceConnected
    C->>M: API内部读取缓存
    M-->>C: 当前缓存，允许是默认值
    C->>C: 向监听器补发状态
    M->>S: SDK连接成功后注册底层回调
    M->>S: 请求自动落锁、ESC状态
    S-->>M: carsetStatusInfos返回实车值
    M->>M: 更新缓存
    M-->>C: 通知实车状态，同值也通知

覆盖：客户端先启动、SDK 晚连接、SDK 回包较慢。客户端可以先显示默认值，随后更新。

2. SDK 已回包，客户端晚启动或晚注册

sequenceDiagram
    participant C as 客户端及API
    participant M as 中间件服务
    participant S as SDK服务
    M->>S: 连接后注册回调并请求状态
    S-->>M: 返回实车状态
    M->>M: 保存状态缓存
    C->>C: 注册状态监听
    C->>M: API内部检查模块连接状态
    M-->>C: 模块已就绪
    C->>C: 通知onServiceConnected
    C->>M: API内部读取缓存
    M-->>C: 已缓存的实车状态
    C->>C: 仅向对应监听器补发状态

覆盖：即使错过之前的实时通知，也能通过快照获取状态。同进程新增监听器只补发给自身，不重复通知已有监听器。

3. SDK 单独断连、重连，中间件仍在线

sequenceDiagram
    participant C as 客户端及API
    participant M as 中间件服务
    participant S as SDK服务
    S-->>M: SDK断连
    M->>M: 保留最后缓存
    C->>C: 继续保持状态监听
    S-->>M: SDK重新连接成功
    M->>S: 重新注册底层回调
    M->>S: 再次请求自动落锁、ESC状态
    S-->>M: 返回最新实车状态
    M->>M: 更新缓存
    M-->>C: 原状态监听通知最新值

SDK 单独重连不需要触发客户端 onServiceConnected()，恢复后的实车回包直接走原状态监听。

覆盖边界

  • 中间件重启：通信恢复、模块重新就绪后再次补发缓存，SDK 连接后主动刷新，组合覆盖图 1、图 2。
  • SDK 始终不回包或通信异常：只能得到默认值或旧缓存，当前没有查询重试，不能保证最终获得实车值。
  • 已反注册：停止通知；再次注册后按图 1 或图 2 处理。
  • 此补发不适用于方控点击、胎压重置完成等瞬时事件。
