Verisoul 机制分析(猜测)

十月 20, 2026 HEIN

这个网站采用“设备与行为采集＋网络主动探测＋风险评分＋问卷项目规则”的多层防刷机制。TLS 指纹是其中一个信号。

1. 整体流程如何运

浏览器侧请求及最终报告支持这条流程；服务器之间获取风险报告的具体调用没有被抓到，图中已标为推断。这与 Verisoul 官方描述的“客户端采集、后台评分、应用执行规则”架构一致。官方架构说明

2. 它具体检查哪些东西

检查维度本项目中的证据作用
交易上下文PID、UID、token、项目、供应商及交易查询将检测结果关联到当前问卷交易
设备和浏览器GPU、字体、音频、屏幕、Worker、WebDriver/CDP、完整性检查等采集字段描述设备环境，检查属性是否一致
网络身份IP、ASN、hosting/isp、位置、信誉评分识别机房网络和其他网络风险
协议与时延ClientHello、HTTP/2 SETTINGS、PING/ACK、STUN检查连接实现和路径是否符合声明环境
用户行为/bhve.js、事件上报及 WebSocket 消息为自动化行为判断提供数据
账户关联device_id、linked_accounts、multiple_accounts 等报告字段支持跨账户、跨会话关联；本次未命中
项目策略threatPotentialScore、终止原因、下一跳 URL决定当前项目是否接受该交易

其中设备采集的 195 个字段来自目录附带的已解码结果，并非本轮重新还原了全部采集算法。

3.  TLS 指纹，在这里对应什么

这是两个不同问题：

  • 内容完整性：请求正文是否经过修改，需要看业务验签等机制。
  • 客户端识别：建立连接的软件实现是否异常，可以参考 TLS、HTTP/2 等特征。

本次抓包直接印证了第二点：

特征Chrome 直连mitmdump 对外连接
HTTP 声明Chrome 155仍声明 Chrome 155
TLS JA4t13d1517h2_8daaf6152771_cb7bf5808d99t13d2812h2_a01be8c064b6_8e6e362c5eac
H2 HEADER_TABLE_SIZE655364096

因此，检测端可以观察到：HTTP 声称是 Chrome，但外部 TLS/H2 连接表现已经改变。

这是 mitmproxy 分别建立上下游 TLS 连接产生的可观测差异；即使不修改正文，也可能出现。mitmproxy 官方原理

不过，JA4 是我们量化差异的方法，不能据此证明网站后台恰好使用了 JA4 算法。它也可能使用原始握手特征或其他指纹。

4. 为什么住宅 IP 仍可能被识别为代理

这套机制会同时检查 IP 属性和实际连接行为。代理组虽然被识别为 ISP 地址，仍出现了：

  • 同用途连接的 SETTINGS→ACK 从直连约 23–25 ms 增为 238–368 ms。
  • HTTP 出口为 71.223.9.152，STUN/UDP 仍从 VPS 的 38.247.162.140 直接出站。
  • TLS/H2 实现与声明的 Chrome 环境出现差异。

代理组保存的最终报告包含：

network_latency_anomaly
network_fingerprint_anomaly
proxy = true
location_spoofing = true

这些现象与官方所描述的主动网络测试、时延分析和协议指纹分析相符。网络检测说明

但不能进一步断言它采用了“某两个 RTT 相减超过固定阈值就封禁”的算法。我们没有后台阈值和原始测时数组；本地抓到的 ACK 回复间隔也不是远端实际测得的完整 RTT。

5. 最终拒绝发生在问卷业务决策阶段

一个很有说明力的结果是，两组最终记录都是：

bot = 0
multiple_accounts = 0
account_score = 1
decision = Fake

也就是说，当前拒绝并不要求先认定“这是机器人”或“这是重复账号”。

直连组存在机房 IP 和设备风险；代理组则存在代理网络异常及相同的设备风险。两组最后都被项目规则终止：

Selected threat potential score at joblevel not allow the survey

这里要区分三个“成功”：

  • /collect 返回成功：采集会话建立成功。
  • saveVeriSoulResponse 返回成功：业务调用处理成功。
  • 是否进入问卷：由后台返回的下一跳及项目规则决定。

本次前两个阶段都成功，最终返回的却都是 status=T 终止回调。官方也将风险评估结果与应用采用的阈值、策略分开处理。评分与决策说明

6. 目前还不能确认的保护

抓包没有证明它对每个业务请求都进行了 HMAC/数字签名验证，也没有还原 token 防重放、限速、验证码或答题质量规则。采集数据的加密、编码和指纹 hash，不能直接视为业务请求验签。

因此，这次最有证据支持的解释是：设备和网络风险被关联到当前问卷交易，随后项目策略拒绝继续。
