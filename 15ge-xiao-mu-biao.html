15个小目标

这个问题我建议别从“技术路线”切，而是从央企体系能不能跑通业务闭环切。

你们的智能座舱业务，最适合的定位不是“再造一个德赛西威/华阳/北斗”，也不是单纯做HMI外包，而是：

以运营商云网能力为底座，做智能座舱的软件平台、云端运营平台、车端中间件和软硬一体解决方案集成商。

换句话说： 不直接卷硬件制造，但要掌握座舱产品定义权、系统集成权、云服务运营权和客户交付入口。

一、先定一个大方向：我们到底该干啥？

我建议业务方向分成四条主线。

方向一：智能座舱软件平台

这是最核心的基本盘。

不要只做一个个项目的HMI开发，而是要沉淀成：

车端操作系统适配层 + 座舱中间件 + 应用框架 + HMI工程平台 + SDK接口体系

你们之前一直在讨论中间件，这个方向是对的。因为单纯HMI项目很难做大，项目结束收入也结束；但中间件、Framework适配、SDK、应用框架一旦标准化，就能跨车型复用。

这个方向解决的是：

  • 不同车厂、不同芯片、不同OS之间的适配问题；
  • HMI与底层能力解耦；
  • 车厂需求变化时减少重复开发；
  • 支撑后续云车机、应用生态、AI座舱。

收入来源：

  • 软件平台授权费；
  • 车型适配费；
  • SDK授权费；
  • 中间件维护费；
  • 项目交付费。

这个方向对应你们的2030年10亿基础目标。

方向二：云车机与座舱SaaS平台

这是你们最应该利用运营商身份做差异化的方向。

行业里很多供应商会做车机、HMI、域控，但不一定擅长云、网、运营、流量、账号、内容分发、远程运维。你们作为运营商体系公司，应该把这个差异打出来。

云车机不要只理解成“云上跑App”。更完整的定义应该是：

车端轻量化 + 云端应用服务 + 远程运维 + 内容分发 + 账号权益 + 流量运营 + 应用生态管理。

这个方向解决的是：

  • 车厂不想自己建设复杂云平台；
  • 后装/商用车/政企车队需要远程管理；
  • 车载应用更新慢、生态弱；
  • 车机硬件性能有限；
  • 运营商流量、内容、权益可以转化为车端服务。

央企现在强调战略性新兴产业、AI+、数字化与新质生产力，国务院国资委披露，2025年中央企业战略性新兴产业投资达到2.5万亿元，占总投资41.8%，研发投入也连续四年超过万亿元；这类“云网+AI+汽车智能化”的业务，比较容易贴合央企战略语言。(21经济网)

收入来源：

  • SaaS平台年费；
  • 车辆连接服务费；
  • OTA/应用管理服务费；
  • 远程运维服务费；
  • 内容/会员/流量运营分成；
  • 政企车队平台建设费。

这个方向对应的是持续性收入，也是你们从项目公司变成平台公司的关键。

方向三：智能座舱AI能力

这个方向不能一开始就喊“做大模型”，容易虚。建议叫：

座舱AI能力平台

具体包括：

  • 车载语音助手；
  • 多模态交互；
  • 行程规划；
  • 车内知识问答；
  • 用户手册问答；
  • 场景推荐；
  • 车控意图理解；
  • 座舱Agent；
  • 明信片/旅途内容生成；
  • 车主服务助手。

你们之前已经做过“行程规划”和“明信片文生图”的大模型能力验证，这正好可以纳入产品体系。

现在智能汽车市场正在从单纯功能配置走向“智能化体验竞争”。新华社2026年报道也提到，2025年消费者对智能辅助驾驶和智能座舱提供的使用价值、情绪价值更加关注，AI技术突破正在加剧市场竞争。(新华网)

收入来源：

  • AI能力包授权；
  • 车厂私有化部署；
  • 模型服务调用费；
  • 场景化应用定制费；
  • 会员权益和运营分成。

这个方向不要单独孤立做，要绑定云车机和座舱软件平台。

方向四：软硬一体解决方案，但不重资产做硬件

这个方向要非常谨慎地表达。

不要说：

我们要做硬件。

应该说：

我们要形成智能座舱软硬一体解决方案能力。

这在央企体系里更容易被接受，因为它不是盲目造硬件，而是为了补齐交付能力。

硬件部分建议采用：

  • 参考硬件平台；
  • 联合ODM/JDM；
  • 生态伙伴供货；
  • 公司负责产品定义、系统集成、软件平台、云服务、测试验收；
  • 硬件制造、结构、供应链、生产由合作伙伴承担。

行业空间是有的。公开资料显示，中国智能汽车销量预计从2025年的2600万辆增长到2030年的4950万辆；智能座舱、智能驾驶、车联网等配置会继续提升单车价值。(HKEX新闻)

但硬件风险也大，所以适合做“解决方案集成”，不适合一开始自建硬件制造体系。

收入来源：

  • 软硬一体整机收入；
  • 系统集成收入；
  • 软件授权收入；
  • 云服务订阅收入；
  • 运维服务收入；
  • 售后服务收入。

这个方向对应的是2030年15亿挑战目标。

二、业务上建议做成“三层战略”

不要一下子把产品铺太散。建议分三层。

第一层：现金流业务

目标是先活下来、形成收入。

适合做：

  1. HMI开发与座舱应用开发；
  2. Framework适配；
  3. 车机系统集成；
  4. 车厂项目交付；
  5. 云车机POC与试点项目；
  6. 政企车队座舱定制项目。

这类业务毛利不一定最高，但容易立项、容易签合同、容易形成案例。

第二层：平台化业务

目标是提高复用率，把项目经验沉淀成产品。

适合做：

  1. 座舱中间件平台；
  2. 车端SDK；
  3. 应用框架；
  4. SaaS运营平台；
  5. OTA与应用管理平台；
  6. AI座舱能力平台。

这类业务是2030年10亿目标的核心。

第三层：规模化业务

目标是扩大收入天花板。

适合做：

  1. 云车机规模化部署；
  2. 软硬一体车机/盒子/座舱域控方案；
  3. 政企/行业车辆智能座舱改造；
  4. 联合车厂量产项目；
  5. 出海或运营商体系内复制；
  6. 车端内容与服务运营。

这类业务是2030年15亿目标的关键。

三、落地产品建议：具体做哪几个产品？

我建议聚焦做 6个产品。不要超过这个数量，否则组织、预算、研发都会被摊薄。

产品一：智能座舱中间件平台

这是最应该优先做的产品。

产品定位

面向车厂、Tier1、座舱项目团队，提供一套统一的车端能力抽象层。

它位于：

HMI / 应用层 ↓ 智能座舱中间件 ↓ Android Framework / HAL / 车控服务 / 系统服务 / 芯片平台

核心能力

包括：

  • 车辆信号服务；
  • 音频服务；
  • 多屏服务；
  • 多用户服务；
  • 应用生命周期管理；
  • 语音控制接口；
  • 蓝牙/媒体/导航/设置统一接口；
  • 账号与权限服务；
  • 场景引擎；
  • 车控Intent分发；
  • 系统状态订阅；
  • 统一SDK。

为什么要做

因为它解决你们当前最痛的问题：

  • 每个车型重复适配；
  • HMI和底层耦合太重；
  • 供应商换一个，接口重来；
  • 项目经验无法复用；
  • 很难从项目开发变成产品公司。

对收入目标的贡献

收入方式2030贡献
平台授权1.5亿—2亿
车型适配1亿—1.5亿
维护服务0.5亿—1亿
合计3亿左右

这个产品是10亿目标的底座。

产品二：智能座舱HMI与应用工程平台

产品定位

不要再把HMI理解成“画界面”。应该把它产品化成：

面向多车型、多屏、多分辨率、多品牌皮肤的座舱HMI工程平台。

核心能力

  • 桌面Launcher；
  • 设置；
  • USB音乐；
  • 蓝牙电话；
  • 视频；
  • 图库；
  • 空调/车控；
  • 导航入口；
  • 多屏联动；
  • 主题皮肤；
  • 多分辨率适配；
  • 快速换肤；
  • 设计资产管理；
  • HMI配置化；
  • 多车型差异管理。

为什么要做

你们已经有HMI项目经验，这是最容易从现有能力转成产品的方向。

但重点是： 不要再一个项目一个项目手工改，而要做成“基础版本 + 车型配置 + 品牌皮肤 + 差异化插件”。

对收入目标的贡献

收入方式2030贡献
HMI项目交付1亿—1.5亿
应用授权0.5亿—1亿
维护升级0.3亿—0.5亿
合计2亿左右

这个产品是短期现金流和案例来源。

产品三：云车机SaaS平台

这是最能体现运营商背景的产品。

产品定位

面向车厂、后装设备商、政企车队、行业车辆，提供云端车机运营与管理平台。

核心能力

  • 设备管理；
  • 车辆管理；
  • 应用商店；
  • 应用上下架；
  • OTA升级；
  • 配置下发；
  • 远程诊断；
  • 日志采集；
  • 异常监控；
  • 内容分发；
  • 流量管理；
  • 账号体系；
  • 权益管理；
  • 数据看板；
  • 运营活动配置。

为什么要做

因为这是你们和传统座舱供应商拉开差异的地方。

传统座舱供应商强在硬件和嵌入式系统；你们更应该强在：

  • 云；
  • 网；
  • 运营；
  • SaaS；
  • 连接；
  • 政企客户；
  • 统一运维。

对收入目标的贡献

收入方式2030贡献
SaaS平台年费1亿—1.5亿
设备连接服务0.5亿—1亿
OTA/应用管理服务0.5亿—1亿
运维服务0.3亿—0.5亿
合计2.5亿—4亿

这个产品是可持续收入的核心。

产品四：座舱AI能力平台

产品定位

面向智能座舱提供统一AI能力，包括语音、多模态、Agent、内容生成、行程规划、场景推荐。

核心能力

建议先做这些：

  1. 行程规划助手；
  2. 车主手册问答；
  3. 车辆功能问答；
  4. 车控意图理解；
  5. 场景推荐；
  6. 明信片/旅途内容生成；
  7. 语音助手增强；
  8. 多模态识别；
  9. AI客服；
  10. 车内主动服务Agent。

为什么要做

AI座舱现在很容易被讲成概念，但真正落地要结合具体场景。

你们不要一开始追求“全能大模型”，而是做：

车端场景 + 云端模型 + 企业私有知识库 + 运营内容生成。

这更容易卖给车厂和政企客户。

对收入目标的贡献

收入方式2030贡献
AI能力包授权0.5亿—1亿
私有化部署0.5亿—1亿
调用服务费0.3亿—0.8亿
运营分成0.2亿—0.5亿
合计1.5亿—3亿

这个产品是提高单车价值和讲战略故事的关键。

产品五：政企/行业车辆智能座舱解决方案

这个产品很适合央企体系。

产品定位

面向政企、行业车辆、商用车、特种车辆、运营车辆，提供智能座舱改造和云端管理方案。

比如：

  • 公务车；
  • 执法车；
  • 应急车；
  • 环卫车；
  • 物流车；
  • 网约车；
  • 出租车；
  • 客运车；
  • 园区车；
  • 工程车。

核心能力

  • 车载智能终端；
  • 行业应用桌面；
  • 任务调度；
  • 车辆定位；
  • 语音通信；
  • 视频回传；
  • 北斗定位；
  • 车况采集；
  • 远程运维；
  • 数据合规；
  • 专网/APN接入；
  • 行业SaaS平台。

为什么要做

这是运营商体系的优势市场。

相比乘用车前装，政企/行业车辆有几个好处：

  • 决策链路更接近央企资源；
  • 更看重安全、合规、专网、运维；
  • 对品牌炫酷度要求低；
  • 对云网服务接受度高；
  • 可以从小批量试点开始；
  • 容易沉淀行业样板。

对收入目标的贡献

运维服务0.3亿—0.5亿
合计3亿—6亿

这个产品是央企体系内最容易规模化突破的方向。

产品六：软硬一体智能座舱参考平台

注意，这不是让你们一上来自己造硬件。

产品定位

做一套可复制的智能座舱参考方案，包括：

  • 参考硬件；
  • Android/OpenHarmony/定制OS；
  • 中间件；
  • HMI；
  • AI助手；
  • 云车机平台；
  • OTA；
  • 应用商店；
  • 运维平台；
  • 测试认证体系。

交付模式

建议三种模式：

模式公司角色适用场景
软件-only软件平台供应商不做硬件的车厂/Tier1项目
软硬一体方案方案主导方后装、行业车、政企车队
联合ODM/JDM产品定义+系统集成有一定规模的终端项目

为什么要做

因为没有这个产品，你们很难回答车厂的质疑：

你们只有HMI，系统和硬件都不是你们的，凭什么做Tier1？

软硬一体参考平台的价值不是马上卖很多硬件，而是补齐客户信任。

对收入目标的贡献

软硬一体项目2亿—5亿
系统集成1亿—2亿
云服务绑定0.5亿—1亿
合计4亿—8亿

这个产品是15亿目标的关键抓手。

四、6个产品之间的关系

不要把这6个产品做成6摊业务。它们应该是一个产品矩阵。

可以这样理解：

                    智能座舱业务目标
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
   车端软件平台          云端运营平台          软硬一体方案
        │                   │                   │
        │                   │                   │
  座舱中间件平台       云车机SaaS平台       参考硬件平台/ODM
  HMI应用工程平台      OTA/应用管理         行业车辆终端方案
  AI座舱能力平台       账号/权益/流量       政企车队解决方案

最核心的产品组合应该是：

中间件平台 + HMI应用平台 + 云车机SaaS + AI座舱能力 + 行业车辆方案 + 软硬一体参考平台

这六个合起来，才能支撑：

  • 不做硬件：2030年10亿；
  • 做软硬一体：2030年15亿以上。

五、按照央企现有体制，应该怎么落地？

这是关键。央企体系里，不能只靠“技术团队自己冲”。必须符合几个逻辑：

1. 先做标准产品，再做项目复制

不能每个项目都重新报价、重新研发、重新交付。要形成：

  • 标准产品包；
  • 标准报价单；
  • 标准合同模板；
  • 标准交付边界；
  • 标准验收指标；
  • 标准运维服务目录。

否则到2030年，收入看着不少，利润和交付能力会很差。

2. 采用“事业群 + 产品线 + 项目制”结合

建议组织方式：

组织单元负责内容
智能座舱产品线产品规划、版本路线、商业模式
车端平台团队中间件、SDK、系统适配
HMI应用团队桌面、设置、多媒体、蓝牙电话等
云平台团队SaaS、OTA、应用商店、运维
AI能力团队大模型、语音、多模态、Agent
行业解决方案团队政企、商用车、后装、车队
项目交付团队车厂项目、量产支持、客户验收
供应链/生态团队ODM、芯片、模组、第三方应用

这比较符合央企现有流程，不会完全打破组织结构。

3. 产品立项要拆成三个阶段

每个产品不要一上来就做“大而全”。建议按央企常见节奏分成：

阶段一：预研立项

目标：证明方向成立。

输出物：

  • 市场分析；
  • 竞品分析；
  • 产品定义；
  • 技术路线；
  • 成本测算；
  • 收入模型；
  • 样机/原型；
  • 客户访谈纪要。

阶段二：产品立项

目标：形成可销售版本。

输出物：

  • PRD；
  • 技术方案；
  • 研发计划；
  • 测试计划；
  • 预算；
  • 商务模型；
  • 交付边界；
  • 标准报价；
  • 试点客户。

阶段三：项目复制

目标：形成规模收入。

输出物：

  • 标准产品包；
  • 标准合同；
  • 交付SOP；
  • 运维SLA；
  • 版本路线图；
  • 客户案例；
  • 行业解决方案白皮书。

六、2030收入目标怎么和产品挂钩？

不做硬件：10亿目标

产品2030收入贡献
智能座舱中间件平台3亿
HMI与座舱应用工程平台2亿
云车机SaaS平台2亿

政企/行业车辆座舱解决方案1亿

这个模型的核心是：

软件平台授权 + 项目交付 + SaaS订阅 + AI能力服务 + 运维运营。

做软硬一体：15亿目标

产品2030收入贡献
智能座舱中间件平台3亿
HMI与座舱应用工程平台2亿
云车机SaaS平台2.5亿
座舱AI能力平台1.5亿

软硬一体参考平台/终端方案3亿

这个模型的核心是：

不自己重资产造硬件，但通过软硬一体方案扩大单项目金额和客户绑定深度。

七、优先级建议：先做哪几个？

我建议分优先级。

P0：必须马上做

1. 智能座舱中间件平台

这是你们从项目公司变成平台公司的关键。

2. 云车机SaaS平台

这是运营商体系的差异化能力。

3. HMI与座舱应用工程平台

这是你们现有经验最容易变现的能力。

P1：第二阶段做

4. 座舱AI能力平台

先从行程规划、车主手册问答、场景推荐、明信片生成做，不要一开始做全能AI座舱。

5. 政企/行业车辆智能座舱方案

这条线适合央企资源和运营商客户体系，应该尽早找样板客户。

P2：谨慎推进

6. 软硬一体参考平台

先做参考设计、样机、联合ODM，不要一上来自己做完整硬件产品。

八、最推荐的落地打法

我建议用一个“三步走”。

第一步：2026—2027，打基础

目标：形成可销售产品雏形。

重点做：

  • 智能座舱中间件V1.0；
  • HMI应用基础套件；
  • 云车机SaaS V1.0；
  • AI行程规划/车主问答/场景推荐；
  • 1—2个政企车辆试点；
  • 1个软硬一体参考样机。

收入目标不要太激进，重点是拿案例和沉淀平台。

第二步：2028，做复制

目标：从项目交付变成产品复制。

重点做：

  • 3—5个车厂/行业客户；
  • 5—10个车型/终端项目；
  • 形成标准产品报价；
  • 建立ODM生态；
  • SaaS平台开始按年收费；
  • 中间件形成多个芯片/系统适配版本。

第三步：2029—2030，做规模

目标：冲10亿/15亿。

重点做：

  • 前装车厂项目规模化；
  • 政企行业车辆规模部署；
  • 云车机平台车辆规模增长；
  • AI能力包商业化；
  • 软硬一体方案带动大项目收入；
  • 形成运营分成和年费收入。

九、内部汇报时可以这样讲

可以直接用这段：

公司智能座舱业务不宜单纯定位为HMI开发商，也不宜重资产进入硬件制造，而应定位为“智能座舱软件平台与云网运营能力提供商”，并逐步形成软硬一体解决方案能力。

短期以HMI、系统集成、中间件和云车机平台形成项目收入；中期通过中间件、SDK、SaaS、AI能力包提升产品复用率；长期通过政企行业车辆、车厂量产项目和联合ODM软硬一体方案扩大收入规模。

在不重资产做硬件的情况下，2030年可通过软件平台、SaaS、项目交付和运营服务形成10亿元收入；在形成软硬一体解决方案能力后，可通过终端方案、系统集成和云服务绑定，将2030年收入目标提升至15亿元以上。

十、一句话总结

你们该干的不是“单纯做硬件”或“继续做HMI项目”，而是：

以智能座舱中间件为车端底座，以云车机SaaS为云端底座，以AI座舱为体验增值，以政企/行业车辆为突破口，以联合ODM软硬一体方案放大收入。

具体落地就做这6个产品：

  1. 智能座舱中间件平台
  2. HMI与座舱应用工程平台
  3. 云车机SaaS平台
  4. 座舱AI能力平台
  5. 政企/行业车辆智能座舱解决方案
  6. 软硬一体智能座舱参考平台

这套组合最符合你们的现实条件： 能立项、能复用、能对外销售、能体现央企云网优势，也能支撑2030年10亿/15亿目标。
